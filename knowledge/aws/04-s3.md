# S3

## Purpose

This document defines how to store objects in **Amazon S3** without leaking them. It covers
public-access blocking, bucket policies vs IAM, encryption, versioning, and lifecycle and
cost controls. S3 is the default place data goes wrong in AWS — the "public bucket" breach
is a genre unto itself — so the rules here are strict.

An S3 bucket name is *globally unique* across all AWS accounts, but the bucket and its data
live in a single Region.

## Why It Matters

S3 breaches are catastrophic and common because the failure is silent: a bucket set to
public serves every object to anyone with the URL, and nothing in the application ever
errors. The data is exposed until someone notices — often a researcher or an attacker. S3
also accumulates cost invisibly: forgotten objects, un-expired versions, and incomplete
multipart uploads pile up for years. The discipline is the same as IAM — closed by default,
opened deliberately, and audited.

## Core Principles

- **Block Public Access, always on.** Enable all four Block Public Access settings at the
  account and bucket level. Public buckets should be a rare, deliberate, reviewed exception
  — usually replaced by CloudFront with Origin Access Control instead.
- **Encrypt everything.** S3 encrypts at rest by default (SSE-S3); use **SSE-KMS** for
  audited, revocable keys on sensitive data. Enforce TLS in transit via bucket policy.
- **Grant access with IAM and scoped bucket policies, not ACLs.** Disable ACLs (Object
  Ownership = Bucket owner enforced); ACLs are the legacy footgun behind most public-object
  incidents.
- **Version and protect against deletion.** Enable versioning so an overwrite or delete is
  recoverable; use MFA delete or Object Lock for data that must not be destroyed.
- **Manage the full lifecycle.** Every bucket needs a lifecycle policy to tier cold data,
  expire old versions, and abort incomplete multipart uploads. Storage is forever otherwise.

## Best Practices

- Serve public web assets through **CloudFront + Origin Access Control**, keeping the bucket
  itself private. Never make the bucket public to serve a website.
- Add a bucket policy that **denies any request where `aws:SecureTransport` is false** so
  plaintext access is impossible.
- Use S3 **Intelligent-Tiering** for data with unknown or changing access patterns; it moves
  objects between tiers automatically with no retrieval fees on the frequent/infrequent
  tiers.
- Enable **S3 Access Logs** or CloudTrail data events on sensitive buckets so access is
  auditable.
- Use presigned URLs for time-limited direct upload/download instead of proxying bytes
  through your application or loosening the policy.
- Turn on lifecycle rules to abort incomplete multipart uploads after ~7 days — a common
  source of silent, un-billed-for-a-reason storage.

## Examples

**Good Example** — private, encrypted, TLS-enforced, versioned bucket (Terraform)

```hcl
resource "aws_s3_bucket" "data" {
  bucket = "acme-prod-user-data"
}

resource "aws_s3_bucket_public_access_block" "data" {
  bucket                  = aws_s3_bucket.data.id
  block_public_acls       = true # all four ON = bucket can never go public by accident
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_versioning" "data" {
  bucket = aws_s3_bucket.data.id
  versioning_configuration { status = "Enabled" } # recover from overwrite/delete
}

resource "aws_s3_bucket_policy" "tls_only" {
  bucket = aws_s3_bucket.data.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Deny"
      Principal = "*"
      Action    = "s3:*"
      Resource  = ["${aws_s3_bucket.data.arn}", "${aws_s3_bucket.data.arn}/*"]
      Condition = { Bool = { "aws:SecureTransport" = "false" } } # block plaintext
    }]
  })
}
```

**Bad Example** — the public bucket

```hcl
resource "aws_s3_bucket" "site" {
  bucket = "acme-public-site"
}

resource "aws_s3_bucket_public_access_block" "site" {
  bucket                  = aws_s3_bucket.site.id
  block_public_policy     = false # public policies now allowed
  restrict_public_buckets = false
}

resource "aws_s3_bucket_policy" "public_read" {
  bucket = aws_s3_bucket.site.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = "*"          # anyone on the internet
      Action    = "s3:GetObject"
      Resource  = "${aws_s3_bucket.site.arn}/*" # every object, forever
    }]
  })
}
# One typo in a prefix or an accidental upload here is a public data leak.
```

## Common Mistakes

- Disabling Block Public Access to "make the website work" instead of using CloudFront.
- Relying on ACLs for access control rather than disabling them and using bucket policies.
- Skipping versioning, so an accidental overwrite or delete is unrecoverable.
- Never adding a lifecycle policy, letting old versions and failed multipart uploads accrue
  cost indefinitely.
- Not enforcing TLS, allowing objects to be fetched over plaintext HTTP.
- Making a bucket public just to share one file, when a presigned URL does it safely and
  temporarily.

## Production Tips

- Run IAM Access Analyzer for S3 and alert on any bucket that becomes externally accessible.
- Enable CloudTrail S3 data events on regulated buckets; standard CloudTrail does not log
  object-level reads/writes.
- For cross-Region durability, enable Cross-Region Replication — S3 does not replicate
  across Regions by default.
- Tag buckets with owner and data-classification so lifecycle and access reviews can be
  automated.

## AI Review Checklist

- Are all four Block Public Access settings enabled at bucket and account level?
- Are ACLs disabled (Bucket owner enforced) and access granted via scoped policies/IAM?
- Is encryption at rest enabled, with SSE-KMS for sensitive data?
- Does a bucket policy deny non-TLS (`aws:SecureTransport = false`) requests?
- Is versioning enabled, with Object Lock/MFA delete where deletion must be prevented?
- Is there a lifecycle policy expiring old versions and aborting incomplete uploads?
- Are public assets served via CloudFront + OAC rather than a public bucket?
