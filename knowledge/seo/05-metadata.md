# SEO Metadata

## Purpose

This document defines the `<head>` metadata that controls how a page is understood and
displayed by search engines: the `<title>`, meta description, `<meta name="robots">`,
canonical link, `viewport`, and language attributes. It is written so an agent can produce
a correct, unique `<head>` per page — the highest-leverage, lowest-effort SEO surface.

Metadata is where you *tell* the engine what a page is and how to show it. Related
per-surface metadata lives in its own docs: [Open Graph](10-open-graph.md) and
[Twitter Cards](11-twitter-cards.md) for social previews, [Structured Data](09-structured-data.md)
for rich results, and [Canonicalization](06-canonicalization.md) for the canonical link in
depth. This doc covers the core search-facing tags and the rules that keep them consistent.

## Why It Matters

The `<title>` and meta description are what a user reads in the search results and decide
whether they click; a duplicated or missing title wastes the single most influential
snippet field you control. Worse, the `<head>` also carries *directives* — a stray
`noindex` or wrong canonical here silently removes the page from results. Because metadata
is usually generated by shared templates, a bug affects thousands of pages at once and is
invisible on the rendered page. Small file, large blast radius.

## Core Principles

- **Every page gets a unique, descriptive `<title>`.** Duplicated titles across pages
  waste the snippet and confuse the engine about which page to rank for a query.
- **Metadata is set server-side.** Titles, descriptions, and canonicals injected only by
  client JS are missed by non-JS bots (see [Rendering](04-rendering.md)); render them in
  the initial HTML.
- **Directives and description are different jobs.** The meta description influences
  *appearance* (and is often rewritten by the engine); `robots` and `canonical` are
  *instructions* that change indexing. Do not treat them casually.
- **Escape dynamic values.** Titles and descriptions built from user or CMS data must be
  HTML-escaped, or a stray `"` or `<` breaks the whole `<head>`.
- **Match the tag to its job.** `description` for the snippet, `canonical` for
  duplicates, `robots` for indexing; the obsolete `keywords` meta is ignored — omit it.

## Best Practices

- Write titles roughly 50–60 characters so they are not truncated; put the distinctive
  term first, brand last (`Wireless Headphones – Acme`).
- Write meta descriptions ~150–160 characters that accurately summarize the page; treat
  them as a click-through pitch, not keyword lists. Unique per page.
- Include exactly one `<title>` and one meta `description` per page — no duplicates from
  layered templates.
- Set a self-referential `<link rel="canonical">` on canonical pages (see
  [Indexing](03-indexing.md)).
- Always include `<meta charset="utf-8">` first and `<meta name="viewport"
  content="width=device-width, initial-scale=1">` for mobile usability.
- Set `<html lang="…">`; for translated pages add `hreflang` alternates (see
  [International SEO](14-international-seo.md)).
- Prefer your framework's typed metadata API (e.g. Next.js `generateMetadata`) so tags
  render on the server and cannot silently drop.

## Examples

**Good Example** — unique, server-rendered, escaped metadata

```tsx
// Next.js App Router: runs on the server, so these tags are in the initial HTML.
export async function generateMetadata({ params }): Promise<Metadata> {
  const product = await getProduct(params.id);
  return {
    title: `${product.name} – Acme`,                 // unique per product, brand last
    description: product.summary.slice(0, 160),       // concise, page-specific
    alternates: { canonical: `https://acme.com/p/${product.id}` }, // self-referential
    robots: { index: true, follow: true },
  };
  // WHY: framework escapes values and emits them server-side, so non-JS bots and
  // social scrapers all receive a correct, unique <head>.
}
```

**Bad Example** — static, duplicated, client-injected, unescaped

```jsx
// Same title on every page + set in the browser only.
function ProductPage({ product }) {
  useEffect(() => {
    document.title = "Products";                     // duplicate across all products;
    // set client-side, so non-JS bots never see it
    const m = document.createElement("meta");
    m.name = "description";
    m.content = product.summary;                     // unescaped: a " or < breaks <head>
    document.head.appendChild(m);
  }, [product]);
  return <h1>{product.name}</h1>;
}
// WHY this is wrong: no server-rendered title/description, every page looks identical
// in results, and unescaped CMS text can corrupt the head markup.
```

## Common Mistakes

- Duplicate or missing `<title>`/description across many pages from a shared template.
- Injecting `<head>` tags only from client JavaScript, so non-JS bots and social
  scrapers get defaults or nothing (see [Rendering](04-rendering.md)).
- Titles far over ~60 chars (truncated) or stuffed with repeated keywords.
- Unescaped dynamic values breaking the `<head>` markup.
- Using the long-dead `<meta name="keywords">` and expecting ranking benefit.
- A `noindex` or wrong `canonical` slipping into the shared `<head>` and deindexing pages.
- Multiple conflicting canonical tags on one page (the engine may ignore all of them).

## Production Tips

- Add a crawl-based test (or a CI HTTP check) asserting every route has a non-empty,
  unique `<title>` and `description` and exactly one canonical.
- Review Search Console's snippet appearance and the "Duplicate title" style warnings
  from audit tools (see [Audits](23-audits.md)).
- Centralize metadata generation in one helper so length limits and escaping are
  enforced in a single place, not copy-pasted per page.

## AI Review Checklist

- Does every page have a unique, descriptive `<title>` (~50–60 chars) and meta description?
- Are all metadata tags rendered server-side, present in the raw HTML?
- Are dynamic title/description values HTML-escaped?
- Is there exactly one `<title>`, one `description`, and one self-referential canonical?
- Are `charset`, `viewport`, and `<html lang>` present?
- Is any `noindex`/wrong-canonical accidentally applied via a shared template?
